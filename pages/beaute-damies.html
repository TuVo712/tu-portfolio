01 / The project

Beauté d’Amies was a Web Programming Studio university team project: a beauty e-commerce website using sample products and content, combining shopping with community discussions.

We developed a dynamic web application and then extended it with database persistence. This was a student project, not a commercial retail service.

02 / What we built

Across the team, the website included product browsing, a cart, beauty content, user accounts, reviews and a discussion forum.

♧Explore

Browse products and beauty content.

♡Manage

Account creation, login and account pages.

✎Discuss

Posts, comments and community interaction.

These were team deliverables; my own contributions focused on the forum, shared account pages and coordination.

03 / My contribution

This was my first experience as team leader. I organised the initial project structure, discussed responsibilities with teammates and helped bring separate modules together.

୨୧ Discussion forum

I developed the discussion forum page and its associated functionality.

୨୧ Shared account pages

I also took on common pages including login, registration, user account and password-recovery flows.

୨୧ Coordination

I initially built the homepage, then reassigned it to another teammate to balance responsibilities.

The finished application was a collaborative team effort, not something I built alone.

04 / Under the hood

The final project used Node.js, Express, EJS templates and MongoDB with Mongoose, alongside HTML, CSS and JavaScript. The repository includes separate controllers and data models for different modules.

HTML / CSS / JavaScriptNode.js + ExpressEJSMongoDB / MongooseGit & GitHub

Scope: Our assessments progressed from in-memory sample data to persistent database storage. Product content was representative, not live retail inventory.

05 / The messy middle

One recurring challenge was integrating teammates’ work. Without an established branching and merging process, changes were sometimes overwritten when code was combined.

I also underestimated how much effort shared functionality would require. When other modules were delayed, I took on additional pages myself, which created an uneven workload.

What I learned: Clear ownership, shared Git conventions and regular integration checkpoints matter just as much as individual coding.

06 / What I took away

This project taught me about communication, delegation and the practical challenges of collaborative web development. If I could start again, I would assign shared modules earlier and agree on the branching workflow before development.

It also gave me a foundation for my second leadership experience in a later Software Engineering project, where I was able to approach coordination with more confidence and experience.
